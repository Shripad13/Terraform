pipeline {
    agent any
    stages {
        stage('Fetch Secrets') {
            steps {
                // withVault automatically authenticates using the global plugin configuration
                withVault(vaultSecrets: [[
                    path: 'secret/data/ci-cd/api-keys', 
                    engineVersion: 2, 
                    secretValues: [
                        [envVar: 'API_TOKEN', vaultKey: 'token']
                    ]
                ]]) {
                    // Inside this block, $API_TOKEN is available and masked in logs
                    sh 'curl -H "Authorization: Bearer $API_TOKEN" https://example.com'
                }
            }
        }
    }
}


To integrate HashiCorp Vault with Jenkins, you should use the HashiCorp Vault Plugin in Jenkins

# Step 1 — Configure Authentication in Vault
set up an AppRole for Jenkins:Enable AppRole: 
vault auth enable approle
Create a Jenkins Policy: Define a policy allowing Jenkins to read paths where your job secrets live.h

path "secret/data/ci-cd/*" {
  capabilities = ["read", "list"]
}

Create the Role: Map the policy to a role

 
 $ vault write auth/approle/role/jenkins-role token_policies="jenkins-policy" token_ttl=1h

Retrieve Credentials: Fetch the role-id and a recurring secret-id to hand over to Jenkins.

# Step 2 — Install and Configure the Jenkins Plugin
In Jenkins, go to Manage Jenkins > Plugins > Available Plugins.

Search for and install the HashiCorp Vault Plugin.

Go to Manage Jenkins > Credentials and save your Vault credentials:
Kind: Vault AppRole Credential
Role ID: Paste the role-id generated by Vault.
Secret ID: Paste the secret-id generated by Vault.

# Step 3 — Define the Vault System Settings
Go to Manage Jenkins > System.Scroll down to the Vault Plugin Configuration section.

Enter your Vault URL (e.g., https://example.com).

Select the Jenkins AppRole credential you saved in Step 2.📝


# Step 4 — Fetch Secrets in your Pipeline

Once configured, use the withVault wrapper inside your Jenkinsfile to retrieve secrets. The plugin handles logging in, fetching the secret, exposing it as an environment variable, and automatically masking it so it never leaks in the build logs.
